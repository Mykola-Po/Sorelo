# Inbox Acceptance Checklist

## Purpose

This checklist records the minimum product pass for the current Inbox triage model.

Use it to confirm the surface behaves like an operator workbench rather than a debug console.

## Checklist

- Create item: a workspace operator can create an Inbox item for a target Map.
- Process item: the item can move through processing and show the current state clearly.
- Clarification path: a pending clarification can be answered and rerun without losing provenance.
- Promote to Learning: promoted or review-bound items expose a clear handoff into the target Map Learning panel.
- Provenance bridge: the item view explains what arrived, what it relates to, what happened, and why.
- Permission/error path: inaccessible, missing, invalid, and conflicting states are handled with clear user-visible outcomes.
- Mobile smoke: the queue and detail flow remain usable on a phone without horizontal fighting or double-scroll confusion.
- Runtime readiness: the Inbox runtime check reports meaningful readiness status and does not expose sensitive operational details.

## Acceptance Standard

Inbox is accepted only when the checklist above is true in product behavior and the current handbook description matches the implemented flow.
